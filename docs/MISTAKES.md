## M-001 — 대상 사용자를 확인하기 전에 엔진(Claude 구독)을 정함 (2026-10-21)
- **무슨 일이:** 설계 v1을 "개발자 본인의 Claude 구독으로 돈다"는 전제로 승인·계획까지 진행. 이후 실제 사용자 대부분이 ChatGPT 유료 + Claude 무료임이 드러남
- **왜:** 사용 대상이 본인인지 여러 사람인지 묻지 않았음
- **영향:** 설계 재작성, v1 구현 계획 폐기 (코드 작성 전이라 손실은 문서뿐)
- **재발 방지:** 설계 초기에 **누가 쓰는지, 그 사람들이 어떤 구독·PC를 가졌는지**를 먼저 확인

## M-002 — 외부 저장소의 "보안 모듈"을 그대로 믿을 뻔함 (2026-10-21)
- **무슨 일이:** hwp-mcp가 경고창 우회용 DLL을 자동 등록하도록 되어 있었음. 확인해 보니 120바이트 깨진 파일
- **영향:** 없음 (테스트 전에 코드 검토로 발견)
- **재발 방지:** 외부 코드는 실행 전 검토, 보안 경고 우회 기능은 쓰지 않음

## M-003 — 한글 연결을 `GetActiveObject`/`Dispatch`로 된다고 가정 (2026-10-22)
- **무슨 일이:** 확인 시험에서 도구 서버가 사용자 창이 아닌 숨은 빈 한글을 새로 띄워 연결 → AI가 빈 본문을 받음. 테스트 문서를 띄운 스크립트가 끝나자 그 한글도 닫힘
- **왜:** hwp-mcp의 `connect()`가 `GetActiveObject` 실패 시 `Dispatch`로 넘어가는 구조를 그대로 믿음. 사용자가 연 한글도 `GetActiveObject`로는 안 잡힘
- **영향:** 시험 1회 실패, 숨은 한글 인스턴스 정리. 사용자 문서 영향 없음
- **재발 방지:** 연결은 ROT의 `!HwpObject*` 열거로만. `Dispatch` 금지. 계획 Task 3 `connect()`에 반영

## M-004 — 시험 스크립트가 사용자의 실제 문서를 수정함 (2026-10-22) ⚠ 심각
- **무슨 일이:** 확인 시험 2차(`mark_test.py`)가 "사용자가 연 한글"에 붙었는데, 그사이 사용자가 실제 업무 문서(앵커사업 운영계획서 .hwp)를 열어 둔 상태였음. 스크립트가 그 문서에서 전체 선택·삭제·문장/표 삽입·음영 지정을 실행
- **왜:** 붙은 뒤 **활성 문서가 시험용 빈 문서인지 확인하지 않음**. 앞 시험 때의 창이 그대로 있으리라 가정
- **영향:** 열린 문서가 메모리에서 변경됨(저장은 안 함 — 디스크 파일 수정 시각 2026-10-21 17:11 그대로). 사용자에게 저장 없이 닫도록 안내
- **재발 방지:**
  - 시험 스크립트는 붙은 뒤 `XHwpDocuments`를 확인해 **경로(`FullName`)가 있는 문서가 활성이면 즉시 중단**. 시험은 스스로 만든 새 문서에서만
  - 제품 코드: 도구 서버는 **사용자가 패널에서 고른 문서**만 대상으로 하고, 작업 전 대상 문서 이름을 패널에 표시
  - `SelectAll`+`Delete` 같은 파괴적 액션은 시험 코드에서도 경로 없는 새 문서에서만

## M-005 — 실제 학생·교원 정보를 테스트·문서 예시에 사용 (2026-10-22)
- **무슨 일이:** 사용자 샘플 문서의 학생 이름·학번, 교원 이름을 테스트 문장·설계 예시·시안에 그대로 씀 (실제 문서 파일은 커밋 안 함)
- **왜:** 예시를 실제 문서에서 바로 가져옴
- **영향:** 비공개 레포의 이전 커밋 이력에 남아 있음. 현재 파일은 가짜 값(홍길동 / 202699001 / 김교수 / 이교수)으로 교체
- **재발 방지:** 예시·테스트에는 항상 가짜 이름·번호. 시험 문장도 실제 문서에서 복사하지 않는다
- **처리 (2026-10-22, 사용자 요청):** `git filter-repo --replace-text`로 모든 커밋에서 실제 이름 1개·학번 1개를 가짜 값으로 교체, 이력 검색 0건 확인. 로컬 시험 출력물(이름 포함)은 휴지통으로. GitHub 반영(강제 푸시)은 사용자 승인 대기
- **남는 위험:** 확인 시험 때 시험 문장(이름·학번 포함)이 ChatGPT(Codex)로 전송된 적 있음 — 되돌릴 수 없음. 이후 시험은 가짜 값만 사용

## M-006 — Claude 앱 안 시험만 보고 "로그인 됨"으로 판단 (2026-10-22)
- **무슨 일이:** 개발 중 로그인·시험을 모두 Claude 앱 안에서 해서 잘 됐지만, 사용자가 직접 띄운 패널은 로그인 화면이 뜨고 로그인 버튼도 실패한 것처럼 보임
- **왜:** Claude 앱(MSIX) 안 프로세스는 `%APPDATA%`가 앱 전용 폴더로 가상화됨. 로그인 정보가 거기에만 있었음
- **영향:** 사용자 혼란, 로그인 1회 추가. 문서 영향 없음
- **재발 방지:** 사용자 환경 확인은 탐색기로 실행(`start_hwp_gpt.bat`)해서 한다. 로그인 출력은 `%APPDATA%\HWP_GPT\login.log`에 남김. 패널 로그인 버튼 실패의 정확한 원인은 이 로그로 다음에 확인

## M-007 — pywin32 창 함수가 GIL을 쥐는지 확인하지 않음 (2026-10-22)
- **무슨 일이:** 사용자가 요청 처리 중 투명도 슬라이더를 움직이자 패널이 "응답 없음"으로 멈춤. 한글 수정은 끝났지만 결과가 화면에 안 옴
- **왜:** `win32gui.SetWindowLong`은 다른 스레드의 창에 쓸 때 그 스레드 응답을 GIL을 쥔 채 기다림. pywebview 화면 스레드는 JS 호출마다 새 파이썬 스레드를 시작하며 GIL을 기다림 → 교착. 작업 스레드에서 패널 창을 바꾸는 코드를 GIL 관점에서 점검하지 않았음
- **영향:** 패널 강제 종료 필요. 한글 문서는 수정된 상태로 남음(저장 안 됨)
- **재발 방지:** 패널 창 스타일 변경은 `dock.set_window_long`(ctypes)만. 새 Win32 호출을 작업 스레드에서 쓸 땐 GIL 해제 여부를 확인(`tests/test_dock_gil.py` 방식)

## M-008 — 사용자 문서의 금액·계산식을 테스트 예시로 씀 (2026-10-22)
- **무슨 일이:** 사용자 화면 캡처에서 본 금액(합계·예산·산출내역 계산식)을 테스트·지침 예시·CHANGELOG에 그대로 씀
- **왜:** 이름·학번만 개인정보로 여기고, 금액도 실제 문서 내용이라는 점을 놓침
- **영향:** GitHub에는 올라가지 않음
- **처리 (2026-10-22, 사용자 요청):** 푸시 전 로컬 커밋 5개(1972400 이후)를 `git filter-branch --tree-filter`로 다시 써서 문서의 금액 4개와 신청일을 가짜 값으로 교체, 이력 검색 0건 확인. 예전 커밋은 reflog에서도 지움
- **재발 방지:** 실제 문서에서 본 숫자·문장은 이름이 아니어도 예시에 쓰지 않는다. 커밋 전 `git diff --cached`에서 사용자 화면에 나온 숫자도 검색

## M-009 — '가짜' 시험 문서가 실제 문서의 문구·숫자를 그대로 씀 (2026-10-22 발견)
- **무슨 일이:** `scripts/make_sample.py`(가짜 데이터 시험 문서)와 테스트·목업에 실제 문서의 행사명, 사업 예산·재료비 금액, 전년도 실적 문장, 학과명, 인원·장소가 그대로 들어 있었음. 이름·학번만 가짜로 바꿨던 것

## M-010 — 가짜 붙여넣기 이벤트로만 시험하고 "된다"고 보고 (2026-10-22)
- **무슨 일이:** 붙여넣기 첨부를 JS로 만든 가짜 paste 이벤트로만 시험해 통과시켰는데, 사용자가 실제 Win+Shift+S → Ctrl+V 하니 안 됨
- **왜:** 가짜 이벤트의 DataTransfer는 언제든 읽히지만, 실제 클립보드 데이터는 이벤트 순간에만 읽힘. 코드가 await 뒤에 읽었음. 시험이 실제 경로(OS 클립보드 + 키 입력)를 거치지 않았음
- **영향:** 사용자 시간 낭비, 공개 배포 전이라 다른 사용자 영향 없음
- **재발 방지:** 입력 장치·클립보드·끌어다 놓기 기능은 실제 OS 경로로 시험 (클립보드에 실제 데이터를 넣고 `keybd_event`로 Ctrl+V). 시험이 흉내만 냈으면 보고에 그렇게 쓴다

## M-013 화면 배율 100% PC에서만 시험해 150% PC에서 패널이 화면 밖으로 (2026-10-25)
- **증상:** 세 번째 PC에서 패널을 띄우자마자 오른쪽이 화면 밖으로 잘림 (사용자 보고)
- **원인:** 창 자리 계산은 실제 픽셀, pywebview의 최소 크기는 배율을 곱한 값 — 패널 폭 380에 배율을 안 곱함
- **재발 방지:** 창 크기·자리를 다루는 코드는 `dpi_scale`을 거친다. 배율 PC가 없으면 최소 폭을 배율만큼 키운 창으로 흉내 시험 (`min_size=(480, …)`로 150% 재현)

## M-014 바꿀 글 안에 찾을 글이 있으면 같은 자리를 여러 번 바꿈 (2026-11-11 점검에서 발견)
- **증상:** `예산A 예산B 예산C`에서 `예산`→`사업 예산` 하면 `사업 사업 사업 예산A 예산B 예산C` (시험 전용 한글로 재현). 문서 내용이 망가짐
- **원인:** `apply()`가 바꾼 뒤 커서를 바꾼 글의 **앞**에 두고 다음 찾기를 해서, 방금 넣은 `사업 예산` 속 `예산`을 다시 찾음. 시험은 바꿀 글에 찾을 글이 없는 경우뿐이었음
- **재발 방지:** 바꾼 글 뒤 자리를 기억해 거기서 다음 찾기. `test_apply_when_replace_contains_find`. 줄 번호를 준 수정은 결과 본문을 예상과 비교해 다르면 되돌림

## M-015 표 칸 글을 기준으로 새 문단을 넣었더니 칸 안에 들어감 (2026-11-11 실제 ChatGPT 시험)

## M-016 확인 시험에서 쪽 그림을 상대 경로로 저장해 시험용 한글이 멈춤 (2026-11-11)

## M-017 꼬리말 넣기가 머리말에 들어감 (2026-11-11 되돌리기 시험에서 발견)
- **증상:** `insert_content`의 footer가 머리말을 만들거나 머리말에 글을 덧붙임
- **원인:** `HHeaderFooter.Type`을 머리말/꼬리말로 짐작함. 실제로는 쪽 종류(양쪽·홀·짝)이고 머리말/꼬리말은 `HeaderFooterCtrlType`. 첫 실기 테스트가 '머리말 글이 HWPML에 있다'만 봐서 못 잡음
- **재발 방지:** 넣은 결과를 종류(`<FOOTER`, 컨트롤 ID `foot`)로 확인하는 테스트. COM 값의 뜻을 짐작하지 말고 결과 구조로 확인

## M-018 창 클래스 이름을 대소문자 그대로 비교 (2026-11-11 발견)
- **증상:** COM으로 띄운 한글(`HwndWrapper[hwp.exe;…]`)을 `find_hwp_window`가 못 찾음 → 그런 한글에는 패널이 안 붙음
- **원인:** 사용자가 직접 띄운 한글의 `Hwp.exe`만 보고 대소문자를 구분해 비교
- **재발 방지:** 창 클래스·파일 이름은 대소문자 무시. `test_find_hwp_window_ignores_exe_name_case`

## M-019 짧은 문구 거부·연도 누락 표시가 문서 전체에 빨간 형광펜을 칠함 (2026-11-11 전체 점검)
- **증상:** 줄 번호 없는 짧은 숫자(`"6"`) 수정을 거부한 뒤 `_check("6", ...)`가 문서 전체의 모든 `"6"`(연도·학번·금액 포함)에 빨간 형광펜을 칠함. `leftover_years`도 `mark_check`에 `nth`를 넘기지 않아 학번 속 연도까지 칠함
- **원인:** 거부된 수정과 실제 확인 대상을 구분하지 않고 무조건 `_mark_all`을 부름
- **재발 방지:** 위치가 없거나 못 찾아서 거부된 짧은 문구는 문서에 형광펜을 칠하지 않고 목록에만 남김. `mark_check`는 `nth`가 있으면 그 번째만 칠함

## M-020 표 안의 사람 이름 칸이 개인정보 보호를 우회함 (2026-11-11 전체 점검)
- **증상:** 참석자 명단 표는 칸마다 한 줄로 읽혀 `'홍길동'` 줄 자체에는 `'이름'`·`'연락처'`가 없어 `is_protected`를 통과함
- **원인:** 문단 단위 검사만 생각하고 표에서 머리글 칸과 값 칸이 다른 줄로 분리되는 점을 놓침
- **재발 방지:** `edit_table`(`set_cell`·`merge`)은 열 머리글(1행)이 개인정보 항목인지 함께 확인하고, `apply_edits`도 `'이름'`·`'성명'` 머리글이 있는 문서에서 학번·연락처 앞뒤의 이름 줄을 보호 대상으로 묶음

## M-021 물품 표 합계 점검(`check_table_sums`)이 행 경계를 넘어 숫자를 중복 합산함 (2026-11-11 전체 점검)
- **증상:** 1행 금액이 `20,000`이고 2행이 `수량 1 × 단가 20,000 = 20,000`일 때, 1행 금액과 2행 수량·단가가 `20,000 × 1 = 20,000`으로 한 번 더 합산되어 정상 표에 합계 불일치 경고가 뜸
- **원인:** `zip(nums, nums[1:], nums[2:])`가 이미 매칭된 3칸(`수량, 단가, 금액`)을 건너뛰지 않고 한 칸씩 밀며 모두 더함
- **재발 방지:** `a * b == c`가 성립해 한 줄의 물품 금액으로 합산한 묶음은 `k += 3`으로 건너뜀

## M-022 `mcp`가 없는 시스템 Python으로 빌드해 `hwpgpt-tools.exe`에 `mcp`가 빠짐 (2026-11-11 빌드 시험에서 발견)
- **증상:** `release.py build --python python`이 통과해 설치 파일이 만들어졌으나, 설치된 `hwpgpt-tools.exe` 실행 시 `ModuleNotFoundError: No module named 'mcp'` 발생
- **원인:** 단위 테스트는 `tools_server.main()`(안에서 `mcp`를 지연 import)을 부르지 않아 시스템 Python(`mcp` 미설치)에서도 통과했고, PyInstaller도 지연 import라 오류 없이 넘어감
- **재발 방지:** `packaging/build.ps1`에서 PyInstaller 실행 전 `import mcp.server.fastmcp, webview, win32com, olefile`을 검사해 필수 패키지가 없는 Python이면 즉시 중단. 빌드 후 `hwpgpt-tools.exe` 실행 응답까지 확인
