# HWP_GPT — 설계

v2 · 2026-10-21 · 상태: **사용자 재검토 대기**
(v1 "한글 옆 Claude 패널"을 대상 사용자에 맞춰 ChatGPT 전용으로 개정. 바뀐 이유는 `docs/MISTAKES.md` M-001)

## 1. 무엇을, 왜

엑셀·파워포인트의 Claude처럼 **한컴 한글 창 오른쪽에 AI 패널을 붙여**, 문서를 띄워 둔 채 말로 고치는 도구. AI 엔진은 **ChatGPT**.

**사용자:** 대부분 **ChatGPT 유료** 사용자(앱 사용자와 웹만 쓰는 사용자 섞여 있음), Claude는 무료라 Claude Code를 쓸 수 없음 → **Claude는 범위에서 제외.**

**주 사용처:** 대학 앵커사업 운영계획서·공문·참석자 명단 등 **해마다 연도만 바꿔 다시 쓰는 서류**. 작년 문서를 열고 "올해 걸로 바꿔줘", "예산 바꾸고 합계 맞춰줘", "추진 배경 새로 써줘"라고 하면 바로 고쳐지고 고친 곳이 표시된다.
실제 사례 문서: 한 파일에 공문 표지·계획서·예산표·참석자 명단·소모품 요구서가 있고 연도가 일부만 바뀐 채(2030/2026/2025 혼재) 남아 있었음. (실제 문서는 개인정보 때문에 레포에 넣지 않음)

**성공 기준:** 엑셀 Claude를 쓸 때처럼 "편하고 빠르다". 연도 갱신 초안이 한 번의 요청으로 대부분 끝나고, 놓친 곳·안 맞는 곳을 AI가 잡아 준다. ChatGPT 유료 사용자가 **추가 비용 없이** 설치해서 바로 쓴다.

## 2. 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| AI 엔진 | **ChatGPT만** (Claude 제외) |
| 화면 배치 | **A안 — 한글 창 오른쪽에 붙는 패널.** 같이 움직이고 한글은 그만큼 좁아짐 |
| 수정 방식 | **먼저 바로 고치고**, 고친 곳을 표시 |
| 기억 | 반복해서 바꾸는 방식을 기억해 다음 요청에 알아서 적용 |
| 직접 고친 것 | 한글에서 손으로 고친 내용도 배움 |
| 기억 저장 | **묻고 저장** — "이렇게 기억할까요?" → 저장 / 고쳐서 저장 / 버리기 |
| 비용 | 사용자의 기존 ChatGPT 구독만. API 키·추가 과금 없음 |
| 저장 | 자동 저장 없음. **최종본은 사용자가 직접 '다른 이름으로 저장'** |
| 개발 기록 | GitHub 레포 `HWP_GPT`에 수정사항·중요 내용·기억할 것·실수를 기록하며 진행 |

## 3. 목표 / 비목표 / 실패로 보는 것

**목표**
- 열린 한글 문서를 COM으로 직접 수정 (글자, 표 셀, 문단 새로 쓰기)
- 바꾼 곳(노랑)·안 바꿨거나 확인할 곳(빨강)을 문서와 패널 목록에 표시, 목록 클릭 → 해당 위치로 이동
- 일관성 점검: 연도·날짜 누락, 날짜↔요일 불일치, 예산 합계 ↔ 본문 "사업 예산" 불일치
- 문서 종류별 기억 쌓기·적용·관리
- 직접 수정에서 규칙 후보 추출 → 물어보고 저장
- **다른 사람 PC에 한 번에 설치** (Python 등 별도 설치 없음, 관리자 권한 없이)

**비목표 (1차)**
- Claude 연결
- 서식 변경 학습·자동 적용, 이미지 속 글자, 빈 문서에서 새로 작성
- macOS, 한컴 없는 PC, 여러 사람이 기억 공유

**실패로 보는 것**
- 학번·실명·연락처 등 개인정보, 식별번호 속 연도(`202699001`) 변경
- 노랑/빨강 표시가 제출할 최종본에 남음
- 묻지 않고 기억 저장, 오타까지 규칙으로 쌓기
- API 키나 추가 비용 요구
- 파일을 몰래 저장·덮어씀
- 사용자의 기존 Codex/ChatGPT 설정(플러그인·설정 파일)을 건드림

## 4. 제약

- Windows 10/11, 한컴오피스 (2022에서 COM `HWPFrame.HwpObject` 검증됨, **다른 버전은 미확인**)
- AI 호출은 **Codex CLI + ChatGPT 로그인**으로만 (ChatGPT 구독의 Codex 사용 한도에서 차감)
- 문서 내용은 AI 호출 외에는 외부로 나가지 않음
- 한글의 파일 접근 확인창 우회 금지 (hwp-mcp의 보안 모듈 DLL은 깨진 스텁 — 사용 안 함)
- 레포에 실제 업무 문서(.hwp/.hwpx) 커밋 금지 — 테스트 문서는 코드로 생성

## 5. 구성 (⚙ = 빌더 판단으로 정한 것)

```
┌──────── 한글 ────────┐┌──── 패널 (WebView2) ────┐
│ 열린 문서            ││ 대화·바꾼 곳·기억 카드  │
└────────▲─────────────┘└───────────┬─────────────┘
         │ COM                       │
┌────────┴──────────────┐   ┌────────┴─────────────────────┐
│ 도구 서버 (MCP, stdio)│◀──│ 패널 앱 (Python)              │
│ 읽기·바꾸기·표시·이동 │   │ 도킹 · 기억 · 학습 · 점검 표시 │
│ + 규칙 엔진 검사      │   │ Codex 실행 (codex exec)       │
└───────────────────────┘   └───────────────────────────────┘
          ▲  Codex가 MCP로 도구 호출
```

- ⚙ **AI 실행: 번들한 Codex CLI**(Apache-2.0)를 패널이 `codex exec --json`으로 실행. **웹만 쓰는 사용자도** 설치본에 Codex가 들어 있으므로 따로 설치할 필요 없음. 첫 실행 때 패널의 [ChatGPT로 로그인] → `codex login`(브라우저에서 ChatGPT 로그인) 1회
- ⚙ **Codex 격리:** 전용 `CODEX_HOME`(`%APPDATA%\HWP_GPT\codex`)을 써서 사용자의 기존 `~/.codex` 설정·플러그인(hj-hwpx 등)과 섞이지 않게 함. 그래서 Codex 앱 사용자도 패널에서 1회 따로 로그인. 도구 서버는 실행 인자(`-c mcp_servers.hwpgpt...`)로만 연결, 파일·셸 접근 없는 읽기 전용 샌드박스
- ⚙ **도구 서버 분리:** 한글 조작은 별도 MCP 서버 프로세스. COM은 그 프로세스의 한 스레드에서만. **규칙 엔진 검사는 도구 서버 안에서** 실행 → AI가 무엇을 요청하든 보호·요일 검사를 통과한 수정만 반영
- ⚙ **언어/배포:** Python + pywebview(WebView2) + pywin32. 배포는 Python 런타임·Codex를 포함한 **설치본(zip 또는 설치 프로그램, `%LOCALAPPDATA%` 설치, 관리자 권한 불필요)**. 방식은 계획 단계에서 확정
- ⚙ **문서 읽기:** COM `GetTextFile`로 메모리에서 본문 받기 (파일 저장·경로 변경 없음)
- ⚙ **수정 표시:** 1순위 한글 **변경 내용 추적**(COM 제어 가능 여부 **미확인 → 첫 확인 시험**), 안 되면 형광펜 + [표시 모두 지우기] + 표시가 남아 있는 동안 상단 경고
- ⚙ **보호·점검 규칙:** hj-hwpx-codex의 검증된 규칙을 코드로 이식 — 개인정보 문단 보호, 식별번호 속 연도 치환 금지, 날짜는 전체 교체 + 요일은 **코드가 계산·검증**, 전년도 실적·서명일은 빨강 확인
- ⚙ **기억 저장소:** `%APPDATA%\HWP_GPT\memory\<문서종류>.md` (사람이 읽고 고칠 수 있는 규칙 목록)
- ⚙ **직접 수정 학습:** AI 수정 직후 본문 스냅샷 → 저장 감지(창 제목) 또는 다음 요청 때 비교 → 의미 있는 변경만 규칙 후보 → 기억 카드로 질문

## 6. 화면 (A안)

머리줄(HWP_GPT · 문서 종류 · 로그인/연결 상태) → 표시 경고 띠(있을 때) → 대화 → 바꾼 곳 목록(🟨/🟥, 클릭 시 이동) → 기억 카드(있을 때) → 입력창.
시안: [docs/mockups/layout-options.html](mockups/layout-options.html)의 A (v1 때 만들어 패널 이름이 Claude로 표시됨).
첫 실행: 한컴 확인 → [ChatGPT로 로그인] → 한글 문서 열기 안내.

## 7. 대표 흐름 — "올해 걸로 바꿔줘"

1. 패널이 문서 종류 기억을 붙여 Codex에 요청
2. Codex가 도구 서버로 본문을 읽고 바꿀 목록을 보냄 → 규칙 엔진 검사 → 위반은 빨강 확인
3. 한글에 바로 반영 + 표시, 패널에 "12곳 바꿈 · 3곳 확인" 목록
4. 예산 변경 시 합계·본문 금액 일치 확인
5. 사용자가 손으로 더 고치고 저장 → 규칙 후보 → "이렇게 기억할까요?"
6. [표시 모두 지우기](형광펜 방식일 때) → 사용자가 직접 '다른 이름으로 저장'

## 9. 미해결·위험

- **이름:** 상표 오해를 피하려고 HANCOM_GPT → HWP_GPT로 변경(2026-10-21). "HWP"는 파일 형식 이름으로 쓰며, 한컴 공식 제품이 아님을 README에 명시
- 한컴 2022 외 버전, 학교 PC(권한·보안 프로그램) 동작 미확인
- ChatGPT 요금제별 Codex 사용 한도 차이 → 무거운 요청에서 한도 도달 가능

## 10. 착수 순서

1. **확인 시험:** ① 변경 내용 추적 COM 제어 ② `GetTextFile` 본문·표 읽기 ③ 전용 `CODEX_HOME` + `codex exec`가 ChatGPT 로그인으로 MCP 도구를 호출하는지 ④ pywebview가 Python 버전에서 뜨는지
2. 규칙 엔진 → 도구 서버 → Codex 연결 → 도킹 패널 → 기억·학습 → 설치본
